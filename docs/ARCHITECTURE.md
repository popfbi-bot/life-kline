# life-kline 架构与决策记录

这份文档写给下一个维护者。它不是产品宣传页，是一份「为什么这么做」的决策记录。
如果你要改动这里的任何一条规则，请先读完它为什么存在。

---

## 1. 核心映射表（股市概念 ↔ 人生含义）

| 股市概念 | 这里的意思 | 说明 |
|---|---|---|
| 开盘 `open` | 早上起来时的状态 | 一天开始时的自评，0–10 |
| 最高 `high` | 当天最好的那个时刻 | 一天里的上限 |
| 最低 `low` | 当天最糟的那个时刻 | 一天里的下限 |
| 收盘 `close` | 睡前时的状态 | 一天结束时的自评 |
| 成交量 `volume` | 这一天做了多少事 | 用户自己填的粗略计数，可空 |
| 停牌 | 那天没记录 | **不是 0 分，是没有数据** |
| K 线 | 一段时间的状态区间 | 日/周/月/年聚合 |
| 均线 | 状态的滑动平均 | 只用来呈现形状 |
| 回撤 | 从之前的高点往下掉了多少 | 描述过去，不预示后面 |

**术语纪律**：面向用户只说「状态」，不说「指数 / 幸福度 / 运势 / 命运」。
「开盘 / 收盘」是内部字段名，交互文案（`presets/ask.md`）里必须换成口语问法。

## 2. 三条诚实红线

这三条是项目的生命线，违反任何一条都应直接驳回。它们不是风格偏好，
而是这个工具能不能被信任的底线。

### 红线一：不做预测

- 指标函数的输入永远截止到「今天」。函数签名里没有「未来日期」这种参数。
- 输出只允许过去时。任何「明天大概率收阳」「趋势将继续」「建议……」都禁止。
- 代码层面的验证：给定前 N 天的数据算出的结果，必须与给全量数据时「前 N 天的部分」逐项一致。
  见 `tests/test_no_lookahead.py`。

原因：一旦工具开始预测，它就从「描述」变成了「指导」。而人一旦被自己画的图指导，
数据就不再诚实了——你会开始为了图好看而改分数。

### 红线二：不插值

- 某天没记录，那天就是空白（停牌）。
- 不许用前一天的值补，不许用均值补，不许用模型猜。
- 图上留空白间隔，不生成 0 值柱，不生成空柱子冒充。
- 空白要**跟得上 K 线的坐标**，也要**让人看得出缺了多久**。见下面「缺口怎么画」。

原因：「有记录」和「没记录」必须在视觉上长得不一样。
「你已经 17 天没记录」本身就是产品要给用户看的信息，
一旦插值，这条信息就被抹掉了。

代价我们也认：图会很稀疏，可能很难看。丑是真实的代价，可以接受。

### 红线三：不装客观

- 所有分数在 UI 和文档里都标「自评」。
- 图例必须写数据来源（`core/render.py` 里的 `source_note`）。
- 不出现「人生指数」「幸福度」「运势」「命运」，统一叫「状态」。

原因：这是一个自我报告的日记本，不是测量仪器。装作客观会让用户把
「我今天自评 4 分」误当成「我今天是 4 分」。

附带一条：标题就叫「状态 K 线」。曾经写过「人生 K 线」，被改掉了 —— 一个自评文件
不该替一整段人生命名。

## 3. 数据模型与校验规则

单文件 CSV，一行一天，人可以手写：

```csv
date,open,high,low,close,volume,note,tags
2026-10-18,6,8,4,7,12,下午把那个 bug 修了,work
2026-10-19,7,7,5,5,8,,tired
2026-10-20,,,,,,,
2026-10-21,5,9,3,8,15,早上很糟下午反转,breakthrough
```

校验规则（`core/model.py`）：

| 规则 | 违反后的行为 |
|---|---|
| `date` 必填，ISO `YYYY-MM-DD`，不得重复 | 报错，定位到行号 + 日期 + 字段 `date` |
| `open/high/low/close` 是 0–10 的整数 | 报错，定位到具体字段 |
| 四个分数**全空** = 停牌 | 合法，不报错 |
| 四个分数**全有值** | 合法 |
| 部分有值（例如有 open 没 close） | 报错，不猜缺失值 |
| `low ≤ open`、`low ≤ close`、`high ≥ open`、`high ≥ close` | 报错 |
| `volume` 可空，非负整数 | 负数报错 |
| `volume` 在停牌日非空 | 报错（停牌就没有成交量） |
| `note` / `tags` 可空 | 不参与任何计算 |

错误信息一律走 `DataError.render()`，格式：

```
第 3 行：2026-10-18 的字段 `high` (4) 不能小于 close (8)
```

绝对不抛裸异常、不抛栈。这是给人手写 CSV 用的工具，报错必须能直接照着改。

`tags` 用分号分隔（不用逗号），因为逗号是 CSV 分隔符。

## 4. 聚合规则

| 周期 | 开盘 | 最高 | 最低 | 收盘 | 成交量 |
|---|---|---|---|---|---|
| 周 | 该周**第一个有记录日**的 open | 该周所有记录的最高 | 该周所有记录的最低 | 该周**最后一个有记录日**的 close | 求和（全空则空） |
| 月 | 同上按月 | 同上 | 同上 | 同上 | 求和 |
| 年 | 同上按年 | 同上 | 同上 | 同上 | 求和 |

两条容易搞错、并且已经写成测试的规则：

1. **必须是「第一个有记录日」，不是「周一」。** 周一停牌就用周二的开盘。
   见 `test_week_open_uses_first_recorded_day`。
2. **整周期全停牌 → 不产生 K 线。** 不许生成一根 0，也不许生成一根空柱子。
   见 `test_fully_suspended_week_has_no_candle`。

周的划分用 ISO 周（`date.isocalendar()`）。副作用是跨年那几天会归到上一年的第 52/53 周，
这是 ISO 标准行为，保留它，别自己发明一套「自然周」。

停牌日不参与开高低收，也不参与成交量求和——它们只贡献「停牌天数」。

## 5. 7 个指标

只做这 7 个。全部是纯函数，在 `core/metrics.py`，不碰文件、不碰网络、不看未来。

| 指标 | 算法 | 边界 |
|---|---|---|
| 日收益率 | `(close_t - close_{t-1}) / close_{t-1}`，与上一个**有记录日**比 | 跨停牌日时直接跨过去 |
| 振幅 | `(high - low) / prev_close` | 同上 |
| 波动率 | 日收益率的**样本**标准差（n−1 分母） | 少于 2 个收益率返回 `None`，不返回 0 |
| 最大回撤 | `max(1 - close_t / max(close_0..close_t))` | 同时记录发生日期与之前的高点日期 |
| 连阳 / 连阴 | 连续 `close > prev_close` / `close < prev_close` 的最长天数 | 平盘（相等）中断连续段 |
| 有记录天数 | 计数 | — |
| 停牌率 | 停牌天数 / 区间总天数 | 区间 = 首个有记录日到末个有记录日 |

**明确不做**：MACD、KDJ、布林带。那些是给交易决策用的，人生不需要。

几个刻意的设计选择：

- 波动率用样本标准差（n−1），注释写清楚。样本量 < 2 时返回 `None`，
  让上层去换说法，而不是输出一个假的 `0.0%`。
- 连阳段里，**日期跨度和根数不是一回事**：`length` 是段内有几天有记录，
  日历跨度（第一根到最后一天，含首尾）**≥ `length`**——中间夹了停牌日，
  跨度就比根数大，一天没停才取等号。
  例：`fixtures/full.csv` 的最长连阳是 3 根（10-23 / 10-29 / 10-31），
  中间夹了 10-24 ~ 10-30 共 6 天停牌，跨度 9 天 > `length` 3。
- 连阳段的 `Segment.start` 记的是**第一根阳线自己的日期**，与 `end`、`length` 对称。
  涨幅的基准是「上一根有记录日」，但基准日不属于这一段，别拿它当起点——
  历史上就是这样把区间整体写早了一天（issue #10）。
  `Segment.first_day` 与 `start` 同值，只是让「展示起点」在调用处一眼可读。

## 5.5 缺口怎么画

这一节单独写，因为这里返工过两次，两次都是真的画错了。

**要同时成立两件事：**

1. 停牌的标记必须落在「真的缺了」的那个空档里；
2. 缺得久，看起来要比缺一天更宽。

**第一次错：** 停牌虚线按日历比例算 x 坐标（`缺口日期/总天数 * 图宽`），
但 K 线是等距排列的。结果虚线落在两根柱子中间偏左的地方，看起来像缺在别的位置。
用户读的是视觉惯性，坐标错了等于信息错了。

修法：虚线的 x 跟着 K 线的槽位走，落在第 `idx` 根与第 `idx+1` 根的正中间。

**第二次错：** K 线纯等距排列，于是「缺 1 天」和「缺 58 天」在图上一样宽。
fixture 里那段 58 天的停牌看起来和一次周末没记录没区别 —— 红线二要传达的信息被抹平了。

修法：`_slot_offsets()` 给缺口按长度加宽度（`_gap_width`）：

| 缺了几天 | 额外占宽 |
|---|---|
| 0 | 0 |
| 1 | 0.3 |
| 2–6 | 0.6 |
| 7–29 | 1.1 |
| ≥30 | 1.6（封顶） |

**为什么不干脆按日历等比铺开？** 试过。记录密集（比如一周记五天）的数据里，
那 58 天的缺口会把其余所有 K 线压成细线，形状完全读不出来。
分档是个折中：缺得久更宽，但宽得有上限，不让停牌变成图的主角。

对应测试：`tests/test_gap_geometry.py`。

## 6. 传播设计：`--mask` 与 `narrate`

### `--mask` 分享模式

`life-kline chart --mask --out share.html`

- 只保留 K 线、均线、成交量柱的**形状**。
- 去掉所有数值：无坐标轴刻度、无图例分数、无 max/min 具体值、无卡片、无折叠指标表。
- 保留相对关系：均线形状、回撤形状都在。
- 必须有水印：`life-kline · 形状可分享，数字只留给自己`。

实现要点（`core/render.py`）：mask 模式下连 `<title>` 提示文本（含分数和日期）都不输出，
否则鼠标悬停就把数字泄露了。测试 `test_mask_removes_numbers` 只检查「文本节点」里的数字，
白名单放行日期和版本号。

形状必须保真：`test_mask_keeps_same_candle_count` 断言 mask 前后 K 线实体数量一致。

### `narrate`：一句自动生成的回顾

由 `core/narrate.py` 生成，公式化地拼事实，不套死模板。

- 数字全部来自实算（`compute_stats`）。
- 月份、日期区间从数据里取。
- 指标不适用时换说法：全年只有 3 天记录、「最长连阳」无从谈起时，
  输出里不会出现「最长连阳 0 天」这种废话。
- 回撤 < 1% 时说「最大回撤不到 1%，收盘价基本没跌破过前高」，不说「回撤 0%」。
- 一天没停牌时说「一天没停牌」，不说「停牌 0 天」。
- 语气克制：无感叹号、无鼓励式措辞。

`test_narrate_uses_real_numbers` 用两份不同数据跑，断言数字随数据变化（防模板化）。

## 7. 职责边界（硬要求）

| 模块 | 职责 | 不许做 |
|---|---|---|
| `core/model.py` | 数据结构与校验 | 不读文件、不算指标 |
| `core/store.py` | CSV 读写，**唯一碰磁盘的模块** | 不算聚合、不算指标（测试 `test_store_does_not_aggregate`） |
| `core/aggregate.py` | 日 → 周/月/年 | 不碰文件、不算指标 |
| `core/metrics.py` | 7 个指标 | 不碰文件（测试 `test_metrics_module_imports_nothing_from_disk`） |
| `core/narrate.py` | 一句回顾 | 不碰文件、不重复算指标 |
| `core/render.py` | 单文件 HTML + 内联 SVG | **不算指标**（测试 `test_render_module_does_not_import_metrics`） |

这条不是为了好看。指标必须能用纯函数测，否则手算期望值无从断言。

## 7.5 空数据与终端输出口径

边界情况下，「没数据」不是错误，但也**不能说假话**。三条命令统一成这样：

| 情况 | 行为 | 退出码 |
|---|---|---|
| 文件里一行数据都没有 | `stats` / `gaps` 提示「还没有任何记录」；`chart` 生成一张空图并说明原因 | 0 |
| `--from/--to` 选中的区间没记录 | `stats` 提示「这个区间里没有数据」 | 0 |
| 区间内全是停牌 | `chart` 生成空图并说明 | 0 |
| 校验失败（字段/OHLC/日期） | 打到 stderr，指出行号 + 日期 + 字段 | 2 |
| 文件不存在 | 提示先 `init` | 2 |

为什么空数据返回 0 而不是 2：刚 `init` 完还没记任何一天，是正常状态，不是失败。
把它当错误会让脚本里的 `set -e` 无端中断。

为什么不许说「一天没停牌」：没数据不等于没停牌 —— 你根本不知道那段时间停没停。
`gaps` 在空数据下说「还没有任何记录」。

两个真实修过的 bug（都补了回归测试，见 `tests/test_empty_data.py`、`tests/test_gaps_output.py`）：

- `suspension_gaps` 原来只扫到**最后一个有记录日**，末尾的停牌日被整段丢掉：
  文件里明明写了「当天停牌」，`gaps` 却报「一天没停牌」，而 `stats` 的停牌率又是对的。
  现在两个函数用同一个区间口径（最早一行到最晚一行）。
- `gaps` 的进度条按比例画，右边却硬编码写 `100%`。现在标签从实算值取，
  测试断言进度条长度与百分比标签一致。

## 8. 技术约束

- **零第三方依赖**，只用 Python 3.10+ 标准库。
- **零网络**：不 import `socket` / `urllib` / `http` / `requests` / `ftplib` / `ssl` / `webbrowser`。
  `tests/test_no_network.py` 用 `ast` 静态扫描全部 `.py`，发现即红。
- **只读 CSV**：除 `add` / `init` 外，任何命令都不写文件（`chart` 只写用户指定的 `--out`）。
- 不写临时文件、不建缓存目录。

## 9. 分期计划

### v0.1（本版）

- CSV 数据模型与校验
- 日/周/月/年聚合
- 7 个指标
- `init` / `add` / `chart` / `stats` / `gaps` / `verify`

- 社交、排行榜、与他人比较
- 任何预测、建议、目标设定
- 移动 App（一个 HTML 文件就够）

## 10. 隐私风险

这个工具的隐私模型很简单：**数据只在本机，工具没有任何上传能力。**

具体保障：

1. 无网络 import（静态扫描保证）。
2. 生成的 HTML 无任何外链资源：没有 CDN、没有字体、没有图片外链、没有 `<script src>`。
   打开这个 HTML 不会发出任何请求。
3. 无遥测、无崩溃上报、无版本检查。
4. 源码可自证：`cli.py` + `core/` 约 1300 行，Python 标准库，读一遍就能确认。

风险点与对策：

| 风险 | 对策 |
|---|---|
| 生成的 HTML 被误发到群里 | `--mask` 只分享形状；README 首屏明确警告 |
| 备注里写了人名/地址 | 备注不参与计算；`--mask` 模式不输出备注 |
| CSV 被同步盘/网盘带走 | 这是用户自己的选择，工具不主动碰除 `--path` 外的路径 |
| 截图时带上其他窗口 | 无法控制，但单文件 HTML 便于在干净窗口里截 |

**不要给这个项目加任何「导出到云端」「生成分享链接」的功能。** 加了就等于破了第 1 条。
